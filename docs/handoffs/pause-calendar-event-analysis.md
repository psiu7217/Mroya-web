# Пауза анализа календарных событий

В Google Calendar оставить подключение аккаунта, выбор календарей для получения событий, календарь назначения для отправки событий из Мрои, кнопку «Синхронизировать» и управление существующим подключением. Автосинхронизация по прежнему контракту обеспечивает получение новых событий без ручного запуска.

- Скрыть «Изучение календарей» и «Углублённый AI-анализ». Отключить запросы, опрос статусов и действия этих модулей в `LiveExperience` и `ConnectionsSettingsView`. Просто убрать панели из JSX недостаточно, так как хуки запускаются отдельно.
- В «Задачах AI» временно убрать календарные `calendar_review` и связанные `memory_proposal`. Для чтения обычных задач чата использовать существующие `GET /api/v1/agent-tasks/` и `GET /api/v1/agent-tasks/<id>/`. Сохранить обычные действия задач чата. Не повторять незавершённые команды анализа, ранее сохранённые клиентом.
- Проверить импорт нового события Google в Мрою и экспорт нового события Мрои в выбранный календарь Google. Проверить сеть при открытии настроек и ручной синхронизации. Клиент обращается к API синхронизации и не обращается к API анализа и углублённой проверки.

## Серверная часть

Успешный импорт вызывает `register_calendar_import` на сервере и может поставить события в очередь первичного отбора независимо от действий клиента. Скрытие функций на вебе и в приложении не останавливает эту автоматику. Сверить отдельно с оператором состояние первичного отбора, вторичной проверки и уже поставленных в очередь календарных задач. Флаг `enabled` сам по себе не останавливает первичный отбор. Пустое `initial_filter_model` прекращает новые захваты первичным фильтром, но не убирает серверную постановку задач в очередь. Для полной паузы календарного контура нужен отдельный серверный гейт, сохраняющий импорт и экспорт.
