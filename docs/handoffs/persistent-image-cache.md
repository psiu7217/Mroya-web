# Кэш изображений и статических ресурсов в Web

Пользователь должен повторно открыть библиотеку, чат или полноразмерное изображение без повторной загрузки уже сохранённых байтов. Изучить текущий загрузчик защищённых изображений, настройки HTTP-кэша и установленный PWA-процесс.

- Использовать браузерное хранилище для уже успешно загруженных оригиналов. Ключ включает идентификатор подтверждённого аккаунта и документа. Превью и просмотр используют одни байты. Одновременные открытия одного документа делят запрос.
- Ограничить объём и срок хранения. Удалять запись при удалении документа. Очищать данные при выходе или смене аккаунта. Неактивный аккаунт теряет доступ к кэшу сразу, включая незавершённые запросы.
- Ошибка или очистка хранилища переводит запрос на существующий API. Ответы API, сессии и CSRF исключены из общего кэша. Для шрифтов и файлов сборки с хешами проверить существующее кэширование браузера перед добавлением второго слоя.
- В тестах после повторного открытия или перезагрузки страницы оригинал приходит из кэша. Проверить сетевой запрос при промахе, повтор после повреждения записи, выход и смену аккаунта.
